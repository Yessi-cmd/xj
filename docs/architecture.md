# 玄鉴技术架构

## 项目边界

玄鉴位于独立的 `xj` 仓库，GitHub 远程为 `Yessi-cmd/xj`。它不依赖 AShare 的目录结构、Python 包或数据库；若两者交换数据，只能通过显式导出文件或版本化 API。

网站采用 React 19、vinext、TypeScript 与 `lunar-javascript`。公网版本构建为纯静态资源，由 Caddy 在 `xj.norliva.top` 提供服务。

## 每日推演链路

1. 新档案从空白草稿开始，性别、出生日期和出生地点必须由用户明确选择，不使用会被误提交的示例默认值。用户可用公历或农历（含闰月）输入出生日期；农历年月日由 `lunar-javascript` 在浏览器本机换算为规范公历 `birthDate`，原始农历选择与历法模式一并保存在档案中。本命指纹只使用规范公历日期，因此同一天的两种录入方式产生完全一致的命盘。旧档案缺少历法字段时继续按公历读取。
2. 用户按“省级 → 市级 → 县区级”逐级选择出生县市，每一级均可按名称筛选。出生时间默认关闭，由用户自主选择是否提供。
3. 用户提供出生时间时，浏览器从静态全国县市快照读取所选地点经度，校正简化真太阳时并生成四柱；未提供时使用正午作为确定性的中性估算，界面明确标记“时柱（估）”和“时辰未录”，避免把估算伪装为精确时辰。
4. 表单底部提供可选进阶本命信息：幸运数字（1-9）、行业偏好（五行行业）、守护神兽（六选一）、晨昏偏好（向阳/向阴）与血型。选定的守护神兽直接成为本命神兽，晨昏偏好决定本命阴阳，血型参与本命主星与卦宫的确定性分配，幸运数字与行业偏好在本命维度小幅加分；全部输入并入本命指纹与排盘键，未设置或旧档案缺失时按中性处理。
5. 系统以 `Asia/Shanghai` 为日期边界生成今日干支、流日五行和幸运提示。
6. 排序器将本命盘、流日、股票标签和反馈画像合成缘分分。
7. 六种职责分别选出守护、上签、潜龙、同曜、补运和相冲签；相冲签不属于正向推荐。
8. 相同本命、日期和换卦版本始终得到相同结果。

恢复本地档案时，客户端会按当前北京时间日期和本命指纹查找用户主动开启的当日星轨：存在时恢复当天已锁定命签，不存在时停留在开签界面等待用户开启。旧版本自动生成但没有主动开签标记的当日记录继续保留在历史中，但不算作今日已开签，也不计入当日连续天数；其遗留换卦计数会在开签前清理。页面持续打开跨过北京时间午夜，或隐藏标签页重新可见、窗口重新获得焦点时，也会重新检查日期并清除昨日展示，不会把旧签冒充今日结果。

首页的流日风水概览也只由同一 `DailyContext` 生成，展示当日五行、取气方位、时辰与起居宜忌。它不读取指数变化，不输出涨跌或交易判断。

缘分分固定为：

```text
本命共振 45%
今日流日 25%
小众探索 15%
用户缘感 10%
基础资格 5%
```

用户缘感只在命理候选中微调，最终影响不超过总分 10%。正向命签执行七日重复冷却；守护签与相冲签不受该冷却影响。守护签随本命盘恒定，不随月份轮换，尊重无感与避开名单；相冲签只排除避开名单。每日可无限次换卦；每次换卦只改变上签、潜龙、同曜和补运。缘分分按固定阈值映射为 S（≥80）、A（≥70）、B（≥60）、C（≥50）、D（<50）五档展示评级，评级只作展示层级，不参与排序。

## 界面导航

桌面端工作台默认释放侧边栏占用的宽度。鼠标进入左侧热区或键盘聚焦展开按钮时，导航从左侧滑入，主内容区按侧栏宽度同步重排；鼠标离开导航或按下 `Escape` 后恢复全宽。

在 900px 及以下视口，导航改为覆盖式左侧抽屉，不挤压主内容。用户可通过页头菜单按钮或从屏幕左缘右滑打开，通过左滑、遮罩、关闭按钮或 `Escape` 关闭。抽屉与按钮保留明确焦点状态，并在减少动态效果的系统设置下关闭过渡动画。

本命页在所有视口都先呈现步骤与录入表单，再呈现每日概览和低频档案工具。六签卡先显示文化命签、取象标签和缘分分；行业、市值、营收及历史涨跌位于默认收起的“静态事实资料”中，避免把事实快照误读成签文结论。主体验、单张签卡和档案迁移分别由 `CompassExperience`、`DailySignCard` 与 `ProfileTransferCard` 承担；基础、每日开签、每日概览和导航样式按职责拆分为独立 CSS 文件。`app/styles/aurora.css` 最后加载，把首页与工作台统一为玄青夜幕视觉（极光底色、宣纸颗粒、鎏金玻璃面板、朱砂警示和动效）；`AmbientEffects` 客户端组件在根布局中绘制装饰星尘画布，并提供指针光斑、签卡微倾与滚动显现。星尘位置使用固定种子，不参与任何命签计算；`prefers-reduced-motion` 下停用全部动效，且未就绪时内容默认可见。用户主动提交生辰时，无论此前是否已有签局，都先展示逐步推进的推演步骤，并至少停留约 2.6 秒再进入今日签局；该停留只是展示节奏，不影响排盘结果，减少动态效果时不额外等待。翻牌开签的牌背与牌面各自做一次性旋转动画，静止时都回到平面，未翻时只有牌背可点，翻开后只有牌面可点，避免 3D 命中测试让背向的牌面拦截点击。

## 股票标签构建

`public/data/mystic-stocks.json` 是需要提交的完整、版本化股票源数据。每只股票可包含：

- 五行主象与副象
- 阴阳、星曜、神兽、卦宫与灵数
- 探索度
- 上市日期与上市日柱
- 交易所方位
- 真实行业及行业五行
- 基本面快照：总市值、市盈率、当日与 5 日涨跌幅、主营业务简介、主营收入与报告期、证监会行业
- 标签版本

`npm run data:refresh` 在构建阶段通过 AkShare 的交易所批量列表补齐上市资料，再使用 `lunar-javascript` 生成上市日柱。缺少行业时不填入占位行业；缺少日期时排序器回退到代码灵数盘。生产页面不在运行时访问 AkShare。

基本面快照由 `scripts/fetch-stock-facts.py` 在 VPS 上抓取（腾讯行情批量接口 + 东方财富 F10 逐股概况与主营构成），结果回传后经 `npm run data:facts:merge` 合并进标签池并升 `schemaVersion`。快照随部署静态发布，签卡展示时标注快照交易日与“不构成投资建议”；个股缺失字段保持为空，页面不在运行时请求行情接口。

`npm run data:runtime` 从完整源生成两个运行时层级：

- `public/data/mystic-stock-index.json`：只保留确定性排序所需的标签字段；
- `public/data/mystic-stock-facts/*.json`：按股票代码前四位分片保存财务与行情事实。

浏览器先加载紧凑索引完成六签排序，再仅请求命中代码所在的本站静态事实分片；请求用源 schema 与事实交易日组成版本参数，并校验分片的源 schema，避免原子发布后混用新旧文件。分片内容不参与排序，因此完整源与紧凑索引对同一本命、日期和换卦版本必须产生相同职责、代码与缘分分。页面不会访问第三方行情接口，也不会在这些静态请求中携带出生信息。总市值字段单位为亿元，东方财富 F10 主营收入字段单位为人民币元，展示层分别换算，不能共用格式化单位。

## 大盘静态快照

`app/data/market-snapshot.json` 是首页大盘概览的版本化数据源，包含 `schemaVersion`、交易日、行情更新时间、抓取时间、快照状态，以及上证指数、深证成指和创业板指的点位与涨跌幅。

`npm run data:market` 是显式联网维护命令，从东方财富行情中心刷新该文件。普通构建、测试和页面加载均不会请求行情接口；VPS 把最后一次已验证快照随版本发布。若快照交易日不是北京时间当天，页面会自动显示“最近大盘快照”和距今天数，不会把旧数据伪装成今日行情。

`npm run data:check` 离线计算自然日年龄。`npm run build:vps` 以严格模式执行该检查，默认拒绝发布早于 7 天的大盘快照或早于 14 天的个股事实快照；测试通过固定日期覆盖该规则，不依赖执行当天。

大盘摘要只按三项指数已经发生的涨跌分为“同步收涨”“同步收跌”“表现分化”或“大致持平”，不与流日风水合并评分，也不推断后市。

## 出生地点数据

`app/data/china-locations.json` 是随前端打包的全国县市静态快照，当前包含 3,304 个城市、区县及港澳台地区条目。大陆行政区划名称基于民政部 2026 年版数据，中心经度由固定版本的 DataV GeoAtlas 数据补齐；新设区划缺少精确中心点时沿用所属城市经度。`npm run data:locations` 是显式的联网维护命令，普通构建、测试和生产页面均不会请求外部地图或地名服务。

档案仍只保存地点显示名称，不新增服务端定位数据。旧版仅保存城市名的档案会按唯一城市名继续解析原有经度；用户通过三级联动重新选择时保存完整的“省 / 市 / 区县”路径，以区分同名县市。

## 本地状态与隐私

全部个人数据保存在版本化浏览器键 `xuanjian.state.v1` 中，包括：

- 本命档案
- 反馈向量和避开名单
- 缘分册
- 最近三十日星轨
- 当日换卦计数

本命档案以公历 `birthDate` 作为排盘基准；用户选择农历时额外保存 `birthCalendar: "lunar"` 与经过校验的 `lunarBirthDate`，旧档案缺少这些字段时不迁移生辰内容。反馈不会重新计算当天已经锁定的结果，只影响未来命签。无感反馈在三十天后同时退出抑制名单与标签权重，避免长期压低标签缘分分；有缘与避开长期保留。读取状态时会逐层归一化档案、反馈、换卦、流日、运势与签卡；只有代码不重复且六种职责齐全的历史签局可以恢复，损坏字段不会直接进入界面，同时缘分册和有效避开反馈不会因无关字段损坏被静默清空。

跨设备迁移使用 `.xjprofile` 文件。用户密码通过 PBKDF2-SHA256 派生密钥，正文由 AES-GCM 加密；文件只保存版本、盐、IV 与密文，密码不落盘。导入可先选择文件，客户端会在派生密钥前限制文件体积、PBKDF2 次数、盐、IV 和密文长度；解密后继续校验内部状态版本，并在覆盖当前档案前确认。分享卡不包含出生日期、时间、地点或登录邮箱。

## 发布

- `npm run build`：先重建股票运行时索引和事实分片，再生成 vinext 构建产物。
- `npm run build:vps`：先执行严格数据新鲜度检查，再生成 `dist-vps/` 静态目录，将 `/live` 渲染为根首页，并校验完整标签池、紧凑索引和事实分片数量。
- Caddy 站点根目录通过版本化 release 和 `current` 符号链接切换，便于快速回滚。

站点始终明确展示“传统文化娱乐体验，不构成投资建议”，不提供实时行情、买卖指令或收益预测。大盘概览仅展示带交易日和更新时间的静态事实快照。

换卦使用玄青鎏金风格的站内确认弹窗，支持键盘操作与 Esc 取消。股票静态事实资料默认折叠，展开后在独立滚动区域展示完整简介，不截断正文；可通过触摸、滚轮和键盘查看。

## RackNerd 低流量自动更新

- RackNerd 使用 `xuanjian-data-update.timer`，按北京时间周一至周五 16:30 执行，随机延迟不超过两分钟；`Persistent=true` 在服务器恢复后补触发。运行前用文件锁避免重复抓取。
- 先用一次三大指数请求检查交易日；交易日未变化时跳过股票抓取和发布（节假日也不会重复全量下载）。每个新交易日刷新批量行情，并在服务器保留最近三十个收盘快照；只请求一次上证指数六根日线来确定五个交易日边界，用对应两日真实收盘价计算五日收盘涨跌（未复权）。未积累够六个交易日或对应日期缺失时，该字段留空，不逐股请求 K 线。公司简介、真实行业和营收等 F10 资料至少间隔七天刷新一次，不再跨日复用 `/tmp` 断点文件。
- 公司资料请求缺失时保留上次真实字段；当日行情缺失字段为空，不伪造新值。发布要求当日行情覆盖率至少 95%、每周公司概况和营收同时有效的覆盖率至少 90%，否则保留当前线上版本。
- 维护源码在 `/opt/xuanjian-updater/source`，独立 Node 运行环境在 `/opt/xuanjian-updater/node`。首次安装依赖后，每日复用依赖在 VPS 本地执行 `npm run build:vps`，不进行 npm 安装或整站往返上传。`scripts/update-vps-data.py` 更新版本化源数据，`scripts/validate-data-release.py` 校验完整池、索引及全部事实分片；构建完成后创建 `auto-data-*` release 并原子切换 `current`，HTTP 或安全头检查失败会切回上一版本。
- `/var/log/xuanjian-data-update.log` 记录抓取请求次数、成功响应体字节数、跳过原因和发布结果（字节数不含 TCP/TLS、HTTP 头以及失败响应流量）；日志每周轮转、压缩，保留八份。`/var/lib/xuanjian-updater/last-success` 和 `last-failure` 保存最近成功、失败记录。使用 `systemctl status xuanjian-data-update.service` 和 `systemctl list-timers xuanjian-data-update.timer` 排查执行状态。
- 三大指数静态快照同时发布为 `data/market-snapshot.json`，页面仍展示构建时注入的版本化数据；生产浏览器不请求第三方行情接口。每周公司资料的抓取时间记录在 `factsSnapshot.profilesCapturedAt`，旧快照缺少该字段时首次执行会刷新公司资料。
- 离线维护测试：`python3 -m unittest discover -s tests -p '*test.py'`；该测试不访问行情源。常规应用验证仍执行 `npm run lint`、`npm test`。
自动更新的大盘首选东方财富；其接口不可用时读取腾讯同一组三大指数的真实收盘数据，并在页面来源字段中标明腾讯行情。不会用旧值推算或填造指数。

后续代码发布必须同步维护源码和 .updater-source-id 标识。自动任务发现线上 release 与维护源码标识不一致时会停止，避免翌日定时构建覆盖人工发布的新功能；初始化显式使用 --force。

完整股票源的 schemaVersion 升为 4，股票命理 tagVersion 仍为 3.0；排序规则不变。五日收盘涨跌明确为未复权口径，自动更新只用真实收盘缓存和指数给出的交易日边界计算，不足时为空。

自动生成的 auto-data-* release 保留最近十四个，并额外保护当前及上一个版本；不会清理原有人工发布版本。公司资料断点只在同一周度抓取周期且未超过七天时复用，成功完成后从该周期最早抓取时间计算下一次刷新。

若服务器在周五收盘后未完成更新、到周末才恢复，持久定时器补触发仍会核对最新交易日并补齐；已保存周五收盘的周末执行直接跳过，不产生行情请求。
